# HU-01 — Protección del token de sesión

## Origen
- **H-WEB-01 — componente `web`**. Evidencia: `web/src/app/core/session.service.ts:13-15,65-73`.

## Contexto
- El token de sesión se guarda en `localStorage`, por lo que permanece accesible desde JavaScript del origen.
- El mecanismo actual no se cambió; falta acordar con backend una estrategia de sesión que no exponga secretos al frontend.

## Ajustes necesarios
- Acordar con backend una estrategia de sesión que impida que el token quede accesible desde JavaScript del frontend.
- Adaptar el manejo de sesión del frontend a la estrategia acordada, conservando el flujo observable de inicio y cierre de sesión.

## Criterios de aceptacion
- Una prueba automatizada del flujo de inicio de sesión verifica que el token de sesión no puede leerse desde JavaScript del frontend.
- Una prueba funcional verifica que, tras iniciar sesión correctamente, se conserva la navegación observada al dashboard sin exponer el token al frontend.
- Una prueba funcional verifica que cerrar sesión devuelve al usuario a login y que la sesión no continúa disponible en el cliente.

## Evidencia esperada
- Resultado de las pruebas automatizadas de confidencialidad del token y del flujo de inicio/cierre de sesión.
- Referencia del acuerdo con backend sobre la estrategia de sesión, sin incluir tokens, secretos ni credenciales.
